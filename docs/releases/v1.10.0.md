# Upgrading to CrewForm 1.10.0

This release collects the personal laptop workers, security hardening, hosted
run enforcement and pricing changes shipped since 1.9.3. Upgrade the backend,
runner and frontend together. The published CLI remains independently versioned
at `@crewformhq/cli@0.2.0`.

## Before changing an existing deployment

1. Export the database schema, Auth/application data and private Storage objects.
   Rehearse a restore without starting schedulers or external integrations.
   Preserve `API_KEY_ENCRYPTION_KEY` separately: replacing it makes existing
   encrypted provider credentials unreadable.
2. Compare the deployed schema and recorded migration history with source.
   Historical duplicate versions and empty migration histories need explicit
   reconciliation. Do not blindly run `supabase db push`, replay seed/cron SQL,
   or apply the unique IDs generated for local evaluation.
3. Follow the baseline checks in [runner operations](../runner-operations.md).
   An older 1.9.3 deployment may also need the security/community changes in
   migrations 085–086 before the reviewed 087–103 upgrade and personal-worker
   migrations 104–105. Apply only missing changes after reviewing the actual
   baseline and testing the upgrade on a restored staging database.

## Coordinated rollout

1. Pause dispatch and scheduled work; allow active work to reach a known terminal
   state. Keep the previous application images and a recoverable database backup.
2. Apply the reviewed database changes through migration 105 once. That migration
   removes `claim_next_task()` without arguments; deploy a runner that calls
   `claim_next_task(p_runner_id)` before resuming work.
3. Deploy matching Edge Functions and runner. Set the same 32-byte hex
   `API_KEY_ENCRYPTION_KEY` in both. Set Edge `TASK_RUNNER_URL` to the trusted runner
   and use the matching `WEBHOOK_SECRET` for the internal outbound guard. Keep
   Supabase API origins distinct from the frontend URL. Preserve each function's
   authentication configuration.
4. Deploy the frontend with the matching Supabase API/build configuration.
   CrewForm requires a complete Supabase backend, not a standalone Postgres
   database. See [self-hosting](../self-hosting.md).
5. Verify runner health, Realtime subscription, tenant authorization and denied
   anonymous wake requests. Resume one primary scheduler after verification.
   Atomic firing claims do not establish Node/Edge cron-parser or enrichment
   parity. Personal-device maintenance is separate from trigger evaluation.

## Pricing and Stripe

Hosted workspace prices are Pro $15/month and Team $49/month. Custom is
on-premises only; provider spend remains separate. Set current monthly USD Stripe
price IDs matching 1500/4900 cents, and retain previous IDs in
`STRIPE_PRO_LEGACY_PRICE_IDS` / `STRIPE_TEAM_LEGACY_PRICE_IDS` for existing
subscriptions. Do not bulk-migrate subscriptions or revoke manual grants during
this upgrade. Review permitted portal prices, proration, trials and downgrade
timing. Billing redirects use `/settings/billing`.

Validate checkout, payment, renewal, delinquency/grace, cancellation, replacement
subscriptions and replayed/out-of-order webhooks in Stripe test mode before
changing your live billing behavior. Existing handler/SQL fixtures and successful
checkout creation do not prove the full account-level payment lifecycle.

## Personal laptop workers

Run `npx @crewformhq/cli@0.2.0 connect`, approve the workspace and agents, then
`npx @crewformhq/cli@0.2.0 worker start`. Configure installed Codex/Claude CLI or
ACP tools locally as described in [local agents](../local-agents.md). Cloud needs
outbound HTTPS from the laptop; it does not need an inbound laptop port or the
provider login credentials. Personal grants expire after 30 days and can be
revoked from Personal devices. Results and logs are uploaded to Cloud.

This release supports personal single-agent jobs. Mixed Cloud/local teams,
account pools, interactive filesystem write approvals and native session resume
remain deferred. Missing native usage is not reported as free inference. The
installed tools and their own account restrictions still apply.

## Rollback and execution limits

General checkpoint/resume is not included. Durable decisions are stored, but
complete executor continuation through approvals remains future work. Interrupted
uncertain work fails for review; do not automatically replay external side effects.

Before reverting personal-worker queue handling, disable new pairing/dispatch,
revoke grants, stop workers and wait for active leases to become terminal. Preserve
results, usage, delivery and audit records. Never route personal-device jobs to a
paid API as a fallback or drop device-assignment data while such jobs exist.

Rollback requires compatible application and database state. Restoring an older
application image alone does not undo schema, billing or encryption changes.
